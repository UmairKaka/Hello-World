# Task Manager

## Project Purpose

This project is a simple task manager for keeping track of daily work.
Users can create tasks, edit them, complete them, and delete them.
The application is designed to make managing tasks quick and easy.

## Coding Conventions

Code should be simple, readable, and easy for another developer to understand.
New code should follow the same style as the existing project.
Developers should avoid unnecessary code and repeated logic.

### Naming

Variables and functions should use clear names that explain their purpose.
Use `camelCase` for variables and functions, such as `taskName` or `createTask`.
Use `PascalCase` for components, such as `TaskList` or `TaskCard`.

### General Rules

Keep each function focused on one main job.
Reuse existing components and functions instead of creating duplicates.
Only change files that are needed for the task being completed.
Keep the code easy to read and understand.

## Project Structure

`src/components/` contains reusable parts of the user interface.
`src/pages/` contains the main screens of the application.
`src/services/` contains code that communicates with external services.
`src/utils/` contains small helper functions used by the application.

## Testing

New features should have tests to check that they work correctly.
Bug fixes should include a test to make sure the same problem does not return.
All existing tests should pass before new code is considered complete.
Tests should be run after making important changes to the application.
